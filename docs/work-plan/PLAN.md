# Рабочий план: FinLens

> Внутренний read-only AI-аналитик для Excel Desktop на Windows.
> Основание: [product brief](../../_bmad-output/planning-artifacts/briefs/brief-excel-extension-bmad-2026-10-14/brief.md).

## Принцип реализации

Не строить каталог фиксированных аналитических сценариев. Пользователь задаёт вопрос свободно; LLM получает выбранный контекст Excel, при необходимости вызывает изолированную Python-песочницу, а затем формирует подробный финансово-аналитический ответ. Надстройка никогда не изменяет книгу.

## Детализация этапов

### 0. Продуктовое видение — готово

- Границы MVP и критерий успеха описаны в product brief.
- Ключевые решения: read-only режим, один внутренний LLM-контур, отсутствие постоянной памяти и внешних данных, видимый пользователю код.

### 1. Требования (PRD) — следующий

- Описать пользовательский путь: открыть Excel → выбрать контекст → задать вопрос → получить ответ, код и график.
- Превратить возможности агента в проверяемые требования: чтение диапазона/листа/книги, объяснение формул, сравнения, аномалии, расчёты, PNG.
- Установить измеримые ограничения: допустимый объём книги, время первого ответа, время вычислений, лимит автоматических повторов кода.
- Зафиксировать критерии приёмки для read-only поведения и отсутствия сохранения истории.
- Результат: PRD, достаточный для UX и архитектуры.

### 2. UX task pane

- Спроектировать одну панель: выбор контекста, чат, индикатор анализа, ответ и ошибки.
- Определить команды `/range`, `/sheet`, `/workbook` и кнопки, которые им соответствуют.
- Продумать показ источников: имена листов и адреса диапазонов, использованных в ответе.
- Спроектировать блок результата песочницы: сворачиваемый Python-код, таблица расчётов, PNG-график, объяснение метода.
- Определить состояния: большая книга, пустой диапазон, ошибка кода, превышен лимит данных, LLM не уверен в выводе.
- Результат: DESIGN.md и EXPERIENCE.md.

### 3. Архитектура

- Выбрать стек task pane и способ доставки add-in в Excel Desktop на Windows.
- Описать read-only контракт Office.js: какие метаданные, значения, формулы и форматы можно читать для каждого выбранного контекста.
- Определить API между add-in и backend: запрос пользователя, снимок данных, карта книги, ответ, таблицы, PNG и события выполнения.
- Спроектировать агентный цикл Qwen: анализ вопроса → tool call к песочнице при необходимости → выполнение → возврат результата/ошибки → максимум две попытки исправления → финальный ответ.
- Спроектировать изоляцию Python: одноразовая среда, только разрешённые библиотеки, без сети, без секретов и без доступа к Excel.
- Зафиксировать, что пользовательской аутентификации нет; если backend требует доступ к внутренним сервисам, его сервисные учётные данные живут только на сервере и недоступны add-in.
- Результат: architecture document и технические решения, достаточные для раздельной реализации компонентов.

### 4. Декомпозиция

- Разбить MVP на эпики: Excel context reader, backend API, карта книги, агент Qwen, sandbox, UI результатов, наблюдаемость и тестирование.
- Для каждой истории указать критерии приёмки, зависимости и проверку read-only ограничения.
- Упорядочить истории так, чтобы сначала появился сквозной путь «вопрос → текстовый ответ», затем песочница и графики.
- Результат: backlog и sprint status.

### 5. Технический фундамент

- Создать каркас Excel add-in с task pane для Windows Desktop.
- Реализовать чтение выделенного диапазона, активного листа и ограниченного used range без операций записи.
- Реализовать backend endpoint и передачу структурированного снимка данных без пользовательского логина.
- Добавить ограничения размера запроса, таймауты и удаление временных данных по завершении сеанса.
- Результат: end-to-end путь Excel → backend → текстовый тестовый ответ.

### 6. Аналитический агент

- Создать системную инструкцию для подробного, доказательного тона финансового аналитика.
- Реализовать сессионную память: история чата и карта только открытой книги; очистка при завершении сеанса.
- Реализовать создание карты книги для `/workbook` и отбор релевантных листов/диапазонов.
- Включить ответ на языке вопроса и обязательную ссылку на использованные данные.
- Результат: агент отвечает на произвольные вопросы о книге без заранее зашитых типов анализа.

### 7. Песочница расчётов

- Определить строгий формат tool call: входные таблицы, цель расчёта, Python-код, текстовые метрики и путь к PNG.
- Запускать код автоматически в изолированной среде с `pandas`, `numpy` и `matplotlib`.
- Возвращать stdout, структурированные таблицы и traceback в агентный цикл.
- Реализовать не более двух автоматических исправлений при ошибке и честную ошибку пользователю при неуспехе.
- Результат: воспроизводимые расчёты и PNG без изменения Excel.

### 8. Интерфейс результатов

- Добавить потоковый вывод ответа, ссылки на листы и диапазоны, таблицы и PNG в чат.
- Показать выполненный Python-код в раскрываемом блоке с возможностью копирования.
- Показать, был ли ответ получен напрямую или с помощью песочницы; отображать состояние повторных попыток без лишней технической сложности.
- Проверить, что UI не предлагает операций записи в книгу.
- Результат: целостный пользовательский опыт MVP.

### 9. Проверка и пилот

- Подготовить набор обезличенных финансовых книг: P&L, бюджет против факта, многолетняя модель, книга с ошибками формул и большая книга.
- Проверить корректность выводов, исполнимость кода, качество графиков, отсутствие записи в Excel и очистку данных после сеанса.
- Замерить время до первого полезного вывода и собрать обратную связь нескольких аналитиков.
- Исправить главные проблемы перед внутренним пилотом.
- Результат: решение о готовности MVP к использованию внутри компании.

## Контрольные точки

### Этапы 1–3 — готовность к реализации

- Есть проверяемые требования, UX и архитектура.
- Пользовательский путь не требует выбора типа анализа: только вопрос и контекст данных.
- Код, созданный LLM, исполняется исключительно в изолированной среде и доступен пользователю для просмотра.
- Для большой книги сначала строится карта структуры; в LLM попадают только релевантные данные.

### Этапы 5–8 — MVP готов к пилоту

- Аналитик может выбрать диапазон, лист или всю книгу и задать произвольный вопрос.
- Система отвечает на языке вопроса, показывает использованные данные и не меняет Excel.
- Расчётный код либо успешно выполнен и показан, либо ошибка честно сообщена после ограниченных повторных попыток.

### Этап 9 — критерий успеха

На тестовой книге аналитик получает полезный, обоснованный и проверяемый простой ответ не более чем за 1 минуту; для ответа с расчётом целевой ориентир составляет до 5 минут до уточнения по пилоту.

## Риски, которые нужно закрыть в архитектуре

- Ограничение объёма данных и времени ответа для больших книг.
- Изоляция сгенерированного Python-кода, запрет сетевого доступа и доступа к секретам.
- Контракт данных между Excel, backend, LLM и песочницей.
- Надёжность Qwen: структурированные tool calls, выполнение кода, возврат ошибки и максимум две автоматические попытки исправления.
- Отсутствие сохранения истории и данных после закрытия сеанса.

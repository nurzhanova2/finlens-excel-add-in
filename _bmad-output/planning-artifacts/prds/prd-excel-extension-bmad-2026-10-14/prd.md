# PRD: FinLens

## 1. Цель

FinLens — внутренний read-only AI-аналитик в task pane Excel Desktop для Windows. Он помогает финансовому аналитику быстро понять незнакомую книгу, проверить модель и получить обоснованные выводы по свободному вопросу без редактирования Excel.

Целевой результат MVP: простой полезный, проверяемый вывод по открытой книге — до 1 минуты; ответ с расчётом — желательный ориентир до 5 минут, который уточняется по итогам пилотных замеров.

## 2. Пользователь и ключевой сценарий

Финансовый аналитик работает с большой числовой таблицей или многолистовой моделью. Он выбирает диапазон, лист или всю книгу, задаёт вопрос своими словами и получает на языке вопроса подробный ответ: вывод, причины, доказательства, риски, допущения и следующую проверку. Если нужны вычисления, агент выполняет их в изолированной Python-песочнице и показывает фактически исполненный код, таблицы и PNG-график.

## 3. Границы MVP

**Входит:** Excel Desktop на Windows; task pane; внутренний Qwen; read-only анализ диапазона, листа и книги; сессионный чат; расчёты, таблицы и PNG в чате.

**Не входит:** изменение ячеек/формул/листов; пользовательская аутентификация; сохранённая история; экспорт отчётов; внешние рыночные и макроэкономические данные; доступ песочницы к интернету.

## 4. Функциональные требования

### Контекст Excel

- **FR-01.** Надстройка должна работать только в Excel Desktop на Windows и открывать FinLens в task pane.
- **FR-02.** Пользователь должен выбирать контекст `range`, `sheet` или `workbook` кнопкой и slash-командами `/range`, `/sheet`, `/workbook`.
- **FR-03.** Панель должна постоянно показывать активный контекст: тип, имя листа и адрес диапазона, когда применимо.
- **FR-04.** Для `range` система должна читать выбранный ограниченный диапазон; для `sheet` — используемый диапазон активного листа; для `workbook` — сначала карту листов и структуры, а затем только относящиеся к вопросу данные.
- **FR-05.** Контекст должен включать значения, формулы, форматы чисел, имена листов и адреса, необходимые для объяснения финансовой модели.
- **FR-06.** Система не должна изменять значения, формулы, листы, графики или структуру книги.

### Диалог с аналитиком

- **FR-07.** Пользователь должен задавать произвольные вопросы свободным текстом; система не ограничивает запросы каталогом фиксированных анализов.
- **FR-08.** Система должна отвечать на языке вопроса пользователя.
- **FR-09.** Ответ должен включать развёрнутый аналитический вывод, а при наличии оснований — причины изменений, риски, аномалии, допущения и следующие проверки.
- **FR-10.** Система должна поддерживать объяснение таблиц и моделей, сравнение периодов/метрик, поиск аномалий, разбор формул, проверку логики и анализ исторических данных.
- **FR-11.** Ответ должен перечислять листы и диапазоны, фактически использованные для вывода.
- **FR-12.** Система должна хранить контекст текущего диалога и карту текущей книги только до конца сеанса.

### Расчёты и графики

- **FR-13.** Агент должен сам определять, нужен ли расчёт; пользователю не требуется выбирать инструмент расчёта.
- **FR-14.** Когда расчёт нужен, система должна автоматически сгенерировать и выполнить Python-код в изолированной песочнице.
- **FR-15.** После успешного расчёта система должна показать пользователю фактически выполненный Python-код, объяснение методики, итоговые таблицы и PNG-графики, если они были созданы.
- **FR-16.** Агент должен использовать в ответе только результаты успешного выполнения кода.
- **FR-17.** При ошибке выполнения система должна передать безопасное описание ошибки модели и допустить не более двух автоматических попыток исправления.
- **FR-18.** После неуспеха всех попыток система должна честно сообщить об ошибке и предложить один понятный следующий шаг, а не выдавать предполагаемый результат за расчёт.

### Состояния и прозрачность

- **FR-19.** Во время обработки панель должна сообщать текущий этап: чтение данных, построение карты книги, вычисление или подготовка вывода.
- **FR-20.** Для большой книги система должна объяснять, что анализируются релевантные части, и показывать использованные листы.
- **FR-21.** Пользователь должен иметь возможность отменить текущий анализ.
- **FR-22.** Панель должна корректно обработать пустой контекст, неподдерживаемую версию Excel, слишком большой объём данных, недостаточность данных и ошибку песочницы.

## 5. Нефункциональные требования

### Безопасность и данные

- **NFR-01.** Данные книги могут передаваться только во внутренний корпоративный LLM-контур и внутренний FinLens API.
- **NFR-02.** Сгенерированный код считается недоверенным: запуск только non-root в одноразовой изолированной среде без сети, host filesystem, секретов и привилегий; разрешены только утверждённые библиотеки (`pandas`, `numpy`, `matplotlib`).
- **NFR-03.** API должен валидировать запросы UI, tool calls Qwen, размеры артефактов и схему результатов до выполнения.
- **NFR-04.** Приложение функционально read-only. Поскольку application-specific Excel API технически требует разрешение `ReadWriteDocument` даже для чтения, гарантия обеспечивается запретом write API, отсутствием доступа песочницы к Office.js и автоматическими тестами неизменности workbook.
- **NFR-05.** Чат, карта книги, временные данные, код, таблицы и PNG удаляются при завершении, отмене или истечении времени сеанса; постоянное хранение запрещено.
- **NFR-06.** Пользовательской аутентификации нет. Любые учётные данные внутреннего Qwen хранятся только на backend; add-in никогда не получает секреты.

### Надёжность и производительность

- **NFR-07.** До включения анализа add-in должен проверять поддержку требуемых Office.js API на runtime; preview API запрещены.
- **NFR-08.** [ASSUMPTION] Для каждого анализа система должна применять лимиты на размер контекста, время ответа, CPU/RAM sandbox и размер PNG; точные значения утверждаются в архитектуре и проверяются на тестовых книгах.
- **NFR-09.** На согласованном наборе типичных тестовых книг простой ответ без песочницы должен быть доступен не более чем за 1 минуту; для ответа с песочницей желательный ориентир — до 5 минут, а окончательный лимит утверждается по итогам пилота.
- **NFR-10.** Ошибки должны быть наблюдаемы через технические метаданные (`analysisId`, время, размер артефакта, outcome), без логирования сырых значений ячеек, промптов, кода или PNG по умолчанию.

### Доступность

- **NFR-11.** Все действия task pane доступны с клавиатуры; порядок Tab соответствует визуальному порядку.
- **NFR-12.** Ошибки, прогресс и успех не должны передаваться только цветом; график должен сопровождаться текстовым описанием.

## 6. Критерии приёмки MVP

1. На обезличенной P&L-книге аналитик выбирает диапазон, задаёт вопрос о сравнении годов и получает на языке вопроса вывод с используемыми диапазонами; книга остаётся неизменной.
2. На многолистовой книге режим `/workbook` сначала создаёт карту, затем отвечает по релевантным листам, не передавая всю книгу в один LLM-контекст.
3. На вопрос, требующий расчёта, пользователь видит выполненный код, расчётную таблицу и PNG; итоговые числа совпадают с эталонным расчётом тестовой книги.
4. На ошибке кода система делает не более двух автоматических исправлений, после чего отображает честную ошибку без сфабрикованного финансового вывода.
5. Попытки кода использовать сеть, host filesystem, секреты, subprocess или запись в Excel блокируются; временные данные удаляются после сеанса.
6. Тест сравнения до/после подтверждает байтовую неизменность workbook после каждого сценария анализа.
7. Панель предлагает понятное действие для пустого контекста, слишком большой книги и неподдерживаемой версии Excel.

## 7. Метрики успеха и ограничения

Главная метрика — доля пилотных сценариев, в которых аналитик получает полезный проверяемый вывод: простой ответ за 1 минуту, ответ с расчётом желательно за 5 минут. Качественный сигнал — ответ содержит причины и доказательства, а не сухое перечисление чисел.

Контрметрики: ложные уверенные выводы, несоответствие кода и текста, изменение Excel, неочищенные данные сеанса, превышение лимитов времени/ресурсов.

## 8. Открытые вопросы

- [ASSUMPTION] Корпоративная сеть должна ограничивать доступ к FinLens API, поскольку пользовательской аутентификации нет.
- [ASSUMPTION] Точные лимиты контекста, sandbox и TTL будут приняты после теста на реальных обезличенных книгах.
- [ASSUMPTION] Поддерживаемый минимум ExcelApi будет выбран после проверки фактически используемых Office.js методов.

topic: AI-аналитик для Excel
updated: 2026-10-14T14:38
---

- (decision) Продукт только анализирует данные Excel; редактирование формул и листов исключено из области.
- (decision) Основные пользователи — финансовые аналитики, работающие с крупными числовыми таблицами и листами Excel.
- (decision) Ключевой сценарий: пользователь задаёт вопрос о таблице, годовых сравнениях или метриках и получает развёрнутый анализ на языке финансового аналитика.
- (decision) Ответы должны содержать причины, выводы, дополнительные идеи и предложения; включают поиск ошибок, объяснение модели, анализ отклонений, прогнозы, проверку отчётности и разбор формул.
- (decision) Пользователь выбирает контекст: выделенный диапазон, текущий лист или вся книга — кнопками либо slash-командами.
- (decision) Результаты: подробный чат-ответ, таблицы и PNG-графики; экспорт отчёта не требуется.
- (decision) Продукт — внутреннее решение компании.
- (decision) Первая версия предназначена только для Excel Desktop на Windows.
- (decision) При обнаружении ошибки формулы ИИ только объясняет проблему и предлагает исправление текстом; книгу не изменяет.
- (decision) PNG-графики отображаются непосредственно в чате task pane и не вставляются в лист.
- (assumption) Данные могут направляться во внешний и внутренний LLM API; требуется уточнить правила маршрутизации и конфиденциальности.
- (decision) Используется только один внутренний корпоративный LLM-контур; пользователь не переключает модели.
- (decision) Критерий успеха MVP: финансовый аналитик получает полезный первый вывод по книге примерно за 1–2 минуты и сокращает ручные сверки.
- (assumption) Внешние рыночные и макроэкономические данные отложены за пределы MVP; для первой версии песочница работает только с данными книги.
- (decision) Выбран совместный (coaching) режим подготовки продуктового брифа.
- (decision) Анализ не ограничивается заранее запрограммированными сценариями: пользователь задаёт произвольный вопрос по книге, а LLM сам определяет требуемый тип аналитической работы.
- (decision) Ответы должны быть живыми, подробными и профессиональными; системная инструкция задаёт роль финансового аналитика, но не жёсткий набор вопросов.
- (decision) LLM при необходимости генерирует Python-код для вычислений и графиков в изолированной песочнице, затем использует результаты для итогового аналитического ответа.
- (decision) Пользователь видит сгенерированный Python-код в чате наряду с объяснением методики и итогом; это обеспечивает прозрачность расчётов.
- (decision) Сгенерированный LLM Python-код запускается автоматически в изолированной песочнице без предварительного подтверждения; он не имеет права изменять Excel.
- (decision) Для режима «вся книга» система сначала строит карту листов и структуры, затем подбирает релевантные листы и диапазоны; в ответе показывает использованные данные.
- (decision) MVP использует сессионную память диалога и карту текущей книги; постоянную память между книгами и сессиями не включает до определения политики хранения.
- (decision) Надёжность генерации кода Qwen обеспечивается циклом: структурированный вызов инструмента → изолированное выполнение → возврат stdout/ошибок → до двух автоматических исправлений → финальный ответ только на основе успешного результата.
- (decision) Рабочее название продукта — FinLens.
- (decision) История чата и результаты не хранятся после закрытия Excel; новый сеанс и файл начинают чистый контекст.
- (decision) FinLens отвечает на языке вопроса пользователя.
- (event) Мемлог аудирован: все продуктовые решения отражены в brief.md; addendum.md не требуется. Черновик отредактирован по замечаниям structure и prose review.
- (event) Артефакт утверждён пользователем и переведён в final.
- (override) Показатель времени уточнён: простой ответ без песочницы — не более 1 минуты; ответ с расчётом — желательный ориентир до 5 минут до пилотного уточнения.

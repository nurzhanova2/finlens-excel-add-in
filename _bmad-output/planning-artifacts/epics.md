# FinLens — Epic Breakdown

## Overview

Документ декомпозирует требования FinLens на реализуемые эпики и истории. На текущем шаге зафиксирован полный реестр требований.

## Requirements Inventory

### Functional Requirements

- FR-01: Работать в Excel Desktop на Windows и открывать FinLens в task pane.
- FR-02: Выбирать контекст range, sheet или workbook кнопкой и командами `/range`, `/sheet`, `/workbook`.
- FR-03: Постоянно показывать активный контекст: тип, лист и адрес диапазона.
- FR-04: Читать ограниченный range, used range листа либо сначала карту workbook и затем релевантные диапазоны.
- FR-05: Передавать значения, формулы, number formats, имена листов и адреса.
- FR-06: Не изменять значения, формулы, листы, графики или структуру книги.
- FR-07: Принимать произвольный вопрос свободным текстом.
- FR-08: Отвечать на языке вопроса.
- FR-09: Давать подробный вывод с причинами, доказательствами, рисками, допущениями и следующими проверками, когда это обосновано.
- FR-10: Поддерживать объяснение моделей, сравнения, аномалии, разбор формул, проверку логики и анализ исторических данных.
- FR-11: Показывать фактически использованные листы и диапазоны.
- FR-12: Держать чат и карту только до конца сеанса.
- FR-13: Самостоятельно решать, нужен ли расчёт.
- FR-14: Автоматически генерировать и выполнять Python-код в изолированной песочнице, когда расчёт нужен.
- FR-15: После успешного расчёта показывать выполненный код, методику, итоговые таблицы и PNG.
- FR-16: Использовать в ответе только успешно выполненные результаты.
- FR-17: Передавать модели безопасное описание ошибки и допускать не более двух исправлений кода.
- FR-18: После неуспеха честно сообщать об ошибке и следующем действии.
- FR-19: Показывать этап обработки.
- FR-20: Для большой книги объяснять выбор релевантных частей и показывать использованные листы.
- FR-21: Позволять отменить текущий анализ.
- FR-22: Обрабатывать пустой контекст, неподдерживаемый Excel, слишком большой объём, недостаточность данных и ошибку песочницы.

### NonFunctional Requirements

- NFR-01: Данные направляются только во внутренний FinLens API и корпоративный LLM-контур.
- NFR-02: Python выполняется non-root, одноразово, без сети, host filesystem, секретов и привилегий; разрешены `pandas`, `numpy`, `matplotlib`.
- NFR-03: API валидирует UI payload, tool calls, размеры артефактов и схему результата.
- NFR-04: Read-only гарантия обеспечивается запретом write API, отсутствием Office.js у sandbox и тестом неизменности workbook.
- NFR-05: Все данные сеанса удаляются при завершении, отмене или TTL; постоянное хранение запрещено.
- NFR-06: Нет пользовательской аутентификации; секреты Qwen остаются на backend.
- NFR-07: Проверять Excel API на runtime; preview API не использовать.
- NFR-08: Применять лимиты контекста, времени, CPU/RAM и PNG; точные значения определить до пилота.
- NFR-09: Давать простой ответ без песочницы не более чем за 1 минуту; для ответа с песочницей ориентироваться на 5 минут до уточнения по пилоту.
- NFR-10: Логировать только технические метаданные, а не ячейки, промпты, код или PNG.
- NFR-11: Обеспечить клавиатурную доступность и логичный Tab order.
- NFR-12: Не передавать состояние только цветом; у PNG есть текстовое описание.

### Additional Requirements

- Task pane — единственный Office.js adapter; backend и sandbox не имеют доступа к Excel.
- API — единственная граница валидации между UI, Qwen и sandbox; доступен один инструмент `run_analysis`.
- `WorkbookMap`, `TabularArtifact`, `AnalysisRequest`, `AnalysisResult` — общие типы контрактов; все сущности используют `analysisId`.
- `AnalysisResult` имеет состояния `completed`, `cancelled` или `failed`; error shape содержит `code`, `message`, `nextAction`.
- Qwen использует OpenAI-compatible tool-calling contract; сервер выполняет максимум две code-fix попытки.
- Sandbox является hardened ephemeral Docker job с allowlist библиотек, лимитами и автоматической очисткой.
- Доступ к внутреннему API ограничивает корпоративная сеть; add-in не содержит секретов и не показывает login UX.
- Манифест и runtime должны ограничить продукт Excel Desktop на Windows и проверить requirement set до старта анализа.

### UX Design Requirements

- UX-DR-01: Одна вертикальная task pane: header/активный context, история, composer; без dashboard.
- UX-DR-02: Реализовать context badge с именем/адресом и мгновенным переключением range/sheet/workbook.
- UX-DR-03: Реализовать composer: Enter отправляет, Shift+Enter переносит строку; новая отправка блокируется во время анализа.
- UX-DR-04: Рендерить ответ структурно: вывод, доказательства, риски/допущения и дальнейшая проверка.
- UX-DR-05: Реализовать раскрываемые блоки Method, Sources, Tables, Code и Chart; Code копируется и показывает только выполненную версию.
- UX-DR-06: Показать PNG во всю ширину панели и открыть увеличенный просмотр по нажатию.
- UX-DR-07: Показывать текстовый прогресс по этапам, включая попытки исправления кода.
- UX-DR-08: Реализовать пустое, loading, large-workbook, success, failed, unsupported-Excel и cancelled состояния с одним понятным следующим действием.
- UX-DR-09: Реализовать отмену анализа и очистку временных артефактов.
- UX-DR-10: Обеспечить keyboard navigation, видимый focus, text labels для состояний и описания PNG.

**FRs covered:** FR-19–FR-22

## Epic 1: Понять выбранные данные Excel

Финансовый аналитик выбирает диапазон, лист или книгу, задаёт свободный вопрос и получает подробный read-only ответ с источниками и памятью текущего сеанса.

### Story 1.1: Открыть совместимую read-only панель FinLens

As a финансовый аналитик,
I want открыть FinLens в Excel Desktop на Windows и сразу понимать, поддерживает ли моя версия Excel анализ,
So that начать работу без риска изменения книги или непонятной ошибки.

**Acceptance Criteria:**

**Given** Excel Desktop на Windows поддерживает требуемый Office.js API
**When** пользователь открывает FinLens
**Then** открывается одна task pane с заголовком, пустой областью диалога и полем вопроса
**And** пользователь не видит login, экспорта или действий изменения Excel.

**Given** Excel не поддерживает необходимый requirement set
**When** открывается FinLens
**Then** панель показывает понятное сообщение о несовместимой версии Excel
**And** отправка вопроса недоступна.

**Given** пользователь работает с поддерживаемой книгой
**When** он открывает или использует FinLens
**Then** в коде надстройки отсутствуют вызовы Office.js, изменяющие workbook
**And** автоматический тест подтверждает неизменность тестовой книги до и после открытия панели.

**Given** пользователь использует клавиатуру или экранный диктор
**When** task pane открыта
**Then** интерактивные элементы имеют доступные подписи, видимый focus и логичный Tab-порядок.

### Story 1.2: Выбрать и прочитать контекст Excel

As a финансовый аналитик,
I want выбрать выделенный диапазон, текущий лист или всю книгу и видеть активный контекст,
So that FinLens анализировал именно те данные, которые мне нужны.

**Acceptance Criteria:**

**Given** FinLens открыт в совместимом Excel
**When** пользователь выбирает кнопку или вводит `/range`, `/sheet` либо `/workbook`
**Then** активный scope меняется на соответствующий тип
**And** контекстная плашка показывает тип, имя листа и адрес диапазона, где это применимо.

**Given** выбран `range`
**When** пользователь начинает анализ
**Then** система создаёт ограниченный снимок выделения со значениями, формулами, number formats, именем листа и адресом
**And** не читает данные за границами выбранного диапазона.

**Given** выбран `sheet`
**When** пользователь начинает анализ
**Then** система читает только used range активного листа с теми же метаданными
**And** не изменяет workbook.

**Given** выбран `workbook`
**When** пользователь начинает анализ
**Then** система создаёт карту листов и их структуры без передачи всей книги как одного неограниченного контекста
**And** сохраняет карту только в рамках текущего сеанса.

**Given** контекст пустой, недоступен или превышает допустимый размер
**When** пользователь пытается отправить вопрос
**Then** FinLens не запускает анализ
**And** показывает понятное действие: выбрать данные, сузить диапазон или использовать другой scope.

**Given** был выбран любой scope
**When** извлечение контекста завершено
**Then** автоматический тест подтверждает, что значения, формулы, листы и структура исходной книги не изменились.

### Story 1.3: Получить ответ на свободный вопрос по диапазону или листу

As a финансовый аналитик,
I want задать свободный вопрос по выбранному диапазону или листу и получить профессиональный ответ с источниками,
So that быстро понять данные без ручного поиска связей.

**Acceptance Criteria:**

**Given** выбран валидный range или sheet
**When** пользователь вводит вопрос и отправляет его
**Then** FinLens передаёт вопрос и ограниченный снимок данных во внутренний API
**And** UI не содержит секретов или учётных данных Qwen.

**Given** внутренний Qwen формирует ответ
**When** результат возвращается в task pane
**Then** ответ дан на языке вопроса
**And** он содержит вывод, доказательства из данных и, когда уместно, причины, риски, допущения и следующую проверку.

**Given** ответ опирается на контекст Excel
**When** он отображается пользователю
**Then** FinLens перечисляет фактически использованные листы и диапазоны
**And** не заявляет использование данных, которых не было в переданном контексте.

**Given** пользователь отправил вопрос, не требующий расчёта
**When** Qwen отвечает
**Then** ответ отображается без блока Python-кода
**And** в UI видны текстовые этапы обработки вместо неопределённого спиннера и ответ на согласованной тестовой книге доступен не более чем за 1 минуту.

**Given** API, Qwen или результат не соответствует ожидаемой схеме
**When** обработка запроса завершается
**Then** пользователь получает понятное сообщение об ошибке и одно следующее действие
**And** технические логи содержат только `analysisId`, время и код ошибки, без сырых ячеек или промпта.

### Story 1.4: Понять большую книгу и продолжить диалог

As a финансовый аналитик,
I want задать вопрос ко всей книге и затем уточнять выводы в том же сеансе,
So that быстро разобраться в многолистовой модели без повторной передачи всей книги.

**Acceptance Criteria:**

**Given** пользователь выбрал `/workbook`
**When** отправляет вопрос
**Then** FinLens строит карту книги с именами листов, используемыми диапазонами и структурными признаками
**And** показывает этап «Строю карту книги».

**Given** карта книги готова
**When** агент отвечает на вопрос
**Then** API передаёт в Qwen только релевантные ограниченные артефакты
**And** ответ перечисляет листы и диапазоны, использованные в выводе.

**Given** пользователь задаёт уточняющий вопрос в том же открытом сеансе
**When** он отправляет вопрос
**Then** FinLens использует историю диалога и карту текущей книги
**And** не требует повторно выбирать scope, пока пользователь его не изменил.

**Given** сеанс завершён, отменён или истёк его TTL
**When** происходит очистка
**Then** история, карта книги, временные артефакты и результаты удаляются
**And** при новом открытии FinLens начинает чистый сеанс.

**Given** книга слишком велика для допустимого контекста
**When** пользователь запрашивает её анализ
**Then** FinLens объясняет ограничение и предлагает сузить вопрос, выбрать лист или диапазон
**And** не передаёт в LLM неограниченный снимок книги.

## Epic 2: Получить проверяемые расчёты и графики

Финансовый аналитик получает автоматически выполненные расчёты, видимый Python-код, таблицы и PNG-графики; система не выдаёт неисполненный расчёт за факт.

### Story 2.1: Выполнить ограниченный Python-расчёт в изолированной песочнице

As a финансовый аналитик,
I want чтобы расчёты по моей книге выполнялись автоматически и безопасно,
So that получать точные результаты без риска для Excel, данных и корпоративной инфраструктуры.

**Acceptance Criteria:**

**Given** агент запросил `run_analysis`
**When** API принимает вызов
**Then** он валидирует JSON-схему, разрешённое имя инструмента, входные артефакты и их размер
**And** отклоняет любые поля с командами, URL, путями файлов или учётными данными.

**Given** вызов валиден
**When** запускается Python-расчёт
**Then** создаётся отдельный ephemeral job от non-root пользователя
**And** он получает только ограниченный табличный артефакт текущего анализа.

**Given** Python-job выполняется
**When** его код пытается обратиться к сети, host filesystem, сокету, секрету или привилегированному процессу
**Then** действие блокируется
**And** sandbox не имеет доступа к Office.js или исходной Excel-книге.

**Given** Python-job выполняется
**When** код импортирует библиотеку
**Then** доступны только утверждённые пакеты `pandas`, `numpy` и `matplotlib` вместе со стандартным безопасным минимумом
**And** неразрешённый импорт завершается контролируемой ошибкой.

**Given** job превышает лимит CPU, памяти, wall-time или output size
**When** лимит достигнут
**Then** job принудительно прекращается
**And** API возвращает типизированный failure с `analysisId`, безопасным сообщением и `nextAction`.

**Given** job завершён, отменён или истёк timeout
**When** cleanup выполняется
**Then** контейнер и временные input/output-артефакты удаляются
**And** в журнале остаются только технические метаданные.

### Story 2.2: Исправить ошибку расчёта без выдумывания результата

As a финансовый аналитик,
I want чтобы FinLens пытался исправить техническую ошибку расчёта, но честно останавливался при неуспехе,
So that не получать убедительный, но недостоверный финансовый вывод.

**Acceptance Criteria:**

**Given** Qwen решает, что нужен расчёт
**When** формируется tool call
**Then** API принимает только инструмент `run_analysis` со строгой схемой
**And** невалидный JSON или обязательные отсутствующие поля не запускают sandbox.

**Given** первый запуск кода завершился ошибкой
**When** API возвращает результат в Qwen
**Then** модель получает ограниченное безопасное описание ошибки и сведения о входных артефактах
**And** не получает секреты, host-path, полные системные логи или данные за пределами scope.

**Given** Qwen сформировал исправленный код
**When** API запускает его повторно
**Then** создаётся новый изолированный job
**And** повтор не использует состояние предыдущего контейнера.

**Given** код продолжает завершаться ошибкой
**When** достигнуты две автоматические попытки исправления после исходного запуска
**Then** дальнейшие повторы прекращаются
**And** `AnalysisResult` получает состояние `failed` с безопасным `code`, `message` и `nextAction`.

**Given** расчёт не был успешно выполнен
**When** формируется ответ в чате
**Then** FinLens не показывает числа или выводы как полученные расчётом
**And** предлагает пользователю сузить scope, уточнить вопрос или проверить входные данные.

### Story 2.3: Показать проверяемые артефакты расчёта

As a финансовый аналитик,
I want видеть, как был получен результат расчёта,
So that самостоятельно проверить вывод FinLens и использовать его в своей работе.

**Acceptance Criteria:**

**Given** sandbox успешно выполнил расчёт
**When** FinLens отображает результат
**Then** пользователь видит аналитический вывод, использованные источники и объяснение методики
**And** вывод ссылается только на фактически выполненный execution artifact.

**Given** выполненный код создал Python-код
**When** отображается сообщение результата
**Then** код показан в раскрываемом моноширинном блоке
**And** пользователь может скопировать именно выполненную версию кода.

**Given** расчёт создал структурированную таблицу
**When** она отображается в чате
**Then** пользователь видит итоговые строки и заголовки
**And** крупная таблица прокручивается или раскрывается внутри блока, не ломая ленту диалога.

**Given** расчёт создал PNG-график
**When** пользователь просматривает результат
**Then** график показывается по ширине панели с текстовым описанием метрики, периода и главного вывода
**And** нажатие открывает увеличенный просмотр без записи изображения на лист Excel.

**Given** расчёт завершился успешно
**When** пользователь проверяет источники и код
**Then** видны фактически использованные листы/диапазоны и `analysisId`
**And** не отображаются секреты, внутренние пути или неисполненные версии кода.

**Given** расчёт требует песочницы
**When** он выполняется на согласованной тестовой книге
**Then** система измеряет время от отправки вопроса до показа результата
**And** целевой ориентир составляет до 5 минут до уточнения окончательного лимита по пилоту.

## Epic 3: Управлять анализом в надёжном интерфейсе

Финансовый аналитик видит ход работы и выбор данных для больших книг, может отменить анализ и получает понятные действия при ошибках, лимитах или неподдерживаемом Excel.

### Story 3.1: Видеть ход анализа и отменять запрос

As a финансовый аналитик,
I want понимать, на каком этапе находится анализ, и при необходимости отменять его,
So that контролировать работу FinLens и не ждать ненужный запрос.

**Acceptance Criteria:**

**Given** пользователь отправил валидный вопрос
**When** начинается обработка
**Then** task pane показывает текстовый этап: «Читаю выбранные данные», «Строю карту книги», «Выполняю расчёт» или «Готовлю вывод»
**And** статус не зависит только от цвета или бесконечного спиннера.

**Given** запрос находится в обработке
**When** пользователь пытается повторно отправить вопрос
**Then** повторная отправка недоступна до завершения или отмены текущего запроса
**And** пользователь видит доступное действие «Отменить анализ».

**Given** пользователь нажал «Отменить анализ»
**When** API получает отмену
**Then** дальнейшая выдача ответа прекращается
**And** sandbox job получает сигнал завершения, если он был запущен.

**Given** отменённый запрос завершает cleanup
**When** UI получает подтверждение
**Then** состояние отображается как `cancelled` с возможностью задать новый вопрос
**And** временные входные и выходные артефакты удаляются.

**Given** сеть или API недоступны во время получения статуса
**When** состояние больше нельзя обновить
**Then** task pane показывает понятную ошибку с действием повторить запрос
**And** не продолжает показывать устаревший прогресс как активный.

### Story 3.2: Получать понятные ответы на ошибки и ограничения

As a финансовый аналитик,
I want получать ясное объяснение, почему FinLens не может завершить анализ,
So that быстро исправить ситуацию, а не разбираться в технической ошибке.

**Acceptance Criteria:**

**Given** активный range пуст, недоступен или не содержит анализируемых данных
**When** пользователь отправляет вопрос
**Then** FinLens не запускает анализ
**And** предлагает выбрать другой диапазон, лист или книгу.

**Given** выбранный scope превышает лимит данных
**When** система оценивает размер запроса
**Then** анализ не передаётся в Qwen или sandbox
**And** сообщение предлагает сузить диапазон, выбрать лист или задать более узкий вопрос.

**Given** данных недостаточно для обоснованного вывода
**When** агент определяет эту ситуацию
**Then** ответ явно описывает недостающие данные или допущение
**And** не маскирует неопределённость уверенным финансовым выводом.

**Given** Qwen, API или sandbox вернули типизированный failure
**When** он отображается пользователю
**Then** сообщение использует безопасный понятный текст и одно применимое следующее действие
**And** не раскрывает секреты, внутренние пути, raw traceback или значения ячеек.

**Given** Excel не поддерживает минимальный requirement set
**When** пользователь открывает FinLens
**Then** интерфейс показывает состояние несовместимости до попытки анализа
**And** направляет пользователя обновить Excel или открыть книгу в поддерживаемой среде.

### Story 3.3: Проверять доступность и прозрачность результата

As a финансовый аналитик,
I want пользоваться FinLens с клавиатуры и ясно понимать, какие данные и результаты вижу,
So that анализ оставался доступным, проверяемым и удобным даже в сложной книге.

**Acceptance Criteria:**

**Given** пользователь перемещается по task pane клавиатурой
**When** использует Tab, Shift+Tab, Enter и Esc
**Then** порядок фокуса соответствует чтению интерфейса
**And** кнопки выбора scope, отправки, отмены, раскрытия кода и закрытия графика доступны без мыши.

**Given** FinLens показывает loading, success, error или cancelled
**When** состояние меняется
**Then** оно имеет текстовую подпись и доступное объявление для screen reader
**And** смысл состояния не передаётся только цветом или иконкой.

**Given** в ответе есть использованные источники
**When** пользователь читает сообщение
**Then** листы и диапазоны показаны точным текстом и доступны для копирования
**And** переход к диапазону выполняется только если платформа его поддерживает.

**Given** результат содержит PNG-график
**When** он отображается или открывается увеличенно
**Then** у графика есть текстовое описание метрики, периода и ключевого вывода
**And** Esc закрывает увеличенный просмотр и возвращает фокус в исходное место.

**Given** `/workbook` использовал только часть большой книги
**When** пользователь просматривает ответ
**Then** FinLens ясно показывает, какие листы и диапазоны были отобраны
**And** пользователь не воспринимает результат как анализ всей книги, если она была ограничена лимитами.
